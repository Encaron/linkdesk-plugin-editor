## 一、一句话

编辑器从「什么文件都硬吃」变成**打开方式体系里的一个普通参与者**：文本类仍归它（它自己声明的 45 个扩展名），二进制不再硬解成乱码，兜底位从「壳里写死的名字」变成「它声明的一个角色」。

**三重身份**（先想清楚再动码）：① 45 个文本扩展名的**持有者**——是**声明**不是特权，第三方可声明同名扩展名竞争（宿主按覆盖表仲裁）；② 兜底位的**当前承担者**——从前是因为壳里写死 `DEFAULT_TAB_TYPE="editor"`，现在这个身份来自它**声明 `role: "text-fallback"`**，第三方文本编辑器声明同角色即可整体接管；③ 兜底呈现的**参考实现者**——「这是不是二进制」**判定归壳**（`EncodingService.isBinary` 一处真相源），「警告怎么画」**归被兜底的插件**（编辑器只是其中一种画法）。

## 三、发版沿革（本案期间的编辑器版本）

| 版本 | 日期 | 这一版为本案做了什么 |
|:--|:--|:--|

**依赖与门槛**：`@linkdesk/plugin-sdk` ^0.1.81——`SHELL_COMMANDS` / `openWith()` 必须从 SDK **子路径** `@linkdesk/plugin-sdk/shell-commands` 取（从根入口取会把 SDK 的构建工具链 vite → rollup 一起打进插件包，Windows 上直接 build 不过）。「打开方式…」钮要求 **LinkDesk 0.2.48+**，更低的软件上它整颗不显示、其余功能一字不变。

**发布实绩（照上架两步走）**：各版均已 `npm run publish` 出 Release **并收录进官方目录**（只收录后才对全体默认用户可见）＋出厂种子已刷到最新。
